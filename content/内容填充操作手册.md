# ShineHome 内容填充操作手册

骨架已经建好（Next.js + 询盘 API），这份手册解决**内容从哪来、怎么填、谁去填、填什么**。

---

## 一、四个内容层，别混在一起填

| 层 | 内容 | 谁负责 | 交付形式 |
|---|---|---|---|
| **L1 产品数据** | 2000+ SKU 的参数、图、价、MOQ | 运营 + 摄影 | CSV 批量导入 CMS |
| **L2 复用文案** | 材质/品类/系列的段落库 | 已写好，见 `lib/copywriter.js` | 代码，自动生成 |
| **L3 品牌故事** | 4 品牌 × 5 系列 | 老板/市场 | 见 `content/brand-stories.json` |
| **L4 公司信任页** | 工厂/品控/认证/物流/售后 | 老板 + 品控 | 见 `content/company-pages.json` |

**关键原则：L1 只填"数据"，不填"文案"。** 运营不该在 2000 行里手写描述——那是 L2 代码的活。

---

## 二、L1 产品数据怎么进 CMS（2000 SKU 的实操路径）

### 第 1 步：准备 CSV（一份，20 列）

```csv
sku,name,brandSlug,seriesSlug,category,material,materialDetail,color,
dimensions,weight,fobPrice,moq,leadTime,coverImage,lifestyleImage,specSheet,
sellingPoint1,sellingPoint2,sellingPoint3,applications
SH-00001,Nordic Loft Classic Sofa 3S,nordic-loft,classic,Sofa,
Top-grain Italian Leather,"1.2mm 全粒面苯胺革, 35D 海绵, 榉木框架",
Cognac,220×95×78 cm,68,320,10,30 days,
/import/SH-00001-cover.jpg,/import/SH-00001-life.jpg,/import/SH-00001-spec.pdf,
,CATAS 认证框架 5 年商用质保,,精品酒店/高端住宅,
```

要点：
- **品牌/系列用 slug 而不是名称**，导入时自动挂 reference，避免拼写不一致
- **图片先传到 Sanity assets 或用 URL**，CSV 只放路径/文件名
- **sellingPoint1-3 只填"这条独有"的**，通用的三条由代码生成
- FOB 价/MOQ 必须真实——买家第一轮询盘就会拿这个跟你算

### 第 2 步：批量导入（三种方式，按能力选）

| 方式 | 适用 | 做法 |
|---|---|---|
| **Sanity CLI + 脚本** | 推荐，最快 | 写 Node 脚本读 CSV → `client.createOrReplace()` 循环，2048 条约 2 分钟 |
| **Sanity 官方 CSV 导入插件** | 不想写代码 | Studio 装 `sanity-plugin-import-tools`，界面上传 |
| **Airtable 中转** | 多人协作录入 | Airtable 建表 → Zapier/脚本同步到 Sanity |

### 第 3 步：图片命名的硬性规范（**这条最容易被忽略，但决定后面累不累**）

```
SH-00001-cover.jpg      主图，白底，2000×2000
SH-00001-life.jpg       场景图
SH-00001-dim.jpg        尺寸标注图
SH-00001-1.jpg ~ -4.jpg 细节/角度图
SH-00001-spec.pdf       规格书
```

2000 个 SKU × 至少 3 图 = 6000 张图。**没有命名规范，后期一定会乱。** 摄影棚交付时就按 SKU 分文件夹。

## 三、L2 复用文案：2000 个详情页怎么不空洞

见 `lib/copywriter.js`，已实现并验证：

- **7 种材质** 各有一段"为什么值这个价"的段落 + 保养说明 + 商用等级
- **7 个品类** 各有工程说明（框架/填充/悬挂）+ 适用场景
- **5 个系列** 各有定位段落
- **合法性约束**：`MATERIAL_BY_CATEGORY` 阻止"皮革做灯具"这类荒谬组合（已测试，2048 条中 0 个非法组合）

调用方式：
```js
import { buildProductCopy } from "@/lib/copywriter";
const { shortDescription, sellingPoints, applications, careGuide } =
  buildProductCopy(product);
```

**为什么这样做**：纯手写 2000 条不可行；纯模板 2000 页雷同会被 Google 判重。组合式生成 = 每个 SKU 拿到的是"品类工程说明 + 材质卖点 + 这条独有的细节"，两全。

> **必须做的补充**：组合文案解决"不空洞"，但解决不了"独特性"。每个 SKU 仍需人工填 **3 条独有卖点**（定制选项、适配项目、竞品对比）。这 3 条是真正决定排名和转化的。2000 条 × 3 条，建议按品类分批，优先填前 200 个主推 SKU。

## 四、L3 品牌故事：怎么写出"卖得动"的故事

见 `content/brand-stories.json`，4 个品牌的结构完全一致：

| 字段 | 作用 |
|---|---|
| `origin` / `eraStyle` | 设计血统——买家需要知道"这是什么流派" |
| `tagline` | 一句话定位 |
| `story`（3–4 段） | ① 传统与设计语言 ② **为什么卖得动**（对买家的商业价值）③ 材料特征 |
| `targetBuyers` | 目标买家，直接对应销售话术和广告投放人群 |
| `priceBand` | 价格带，帮买家快速判断是否配得上自己的渠道 |

**写作要点**：每段都要回答"这对买家有什么好处"。写"我们采用丹麦工艺"没用；写"丹麦现代设计在买家端有普遍认知度，且出片率高，能带动零售伙伴的电商转化"才有用。

## 五、L4 公司信任页：B2B 转化率的真正杠杆

见 `content/company-pages.json`，7 个页面已写好英文成稿：

| 页面 | 路由 | 回答买家的什么疑虑 |
|---|---|---|
| About | `/about` | 你们是谁，凭什么 |
| Factory | `/factory` | 真有厂吗 |
| Quality Control | `/quality-control` | 品质怎么保证 |
| Certifications | `/certifications` | 能过海关和我客户的采购审计吗 |
| Custom & OEM | `/custom-oem` | 能按我的要求改吗 |
| Logistics | `/logistics` | FOB/CIF/DDP 怎么走 |
| After-Sales | `/after-sales` | 出问题谁负责 |

> **⚠️ 所有 `[方括号]` 都是待填的真实数据。** B2B 买家会核对——写"32,000 m² 厂房"就得有对应的照片和视频。宁可写小一点的真实数字，也不要写大的假数字。

## 六、上线前的内容检查清单

- [ ] 2000 SKU 全部有：1 张主图 + 1 张场景图 + 尺寸图 + 规格书 PDF
- [ ] 前 200 个主推 SKU 填完 3 条独有卖点
- [ ] 4 个品牌页、5 个系列页全部有故事文案
- [ ] 7 个信任页 `[方括号]` 全部替换为真实数据
- [ ] 每个产品页 meta title/description 非空（用 `名称 + 品类 + replica + wholesale` 模板批量生成）
- [ ] 工厂/车间/展厅/装柜 实拍照片至少各 5 张
- [ ] 认证证书扫描件（可打水印，但要有）
- [ ] 至少 3 个客户案例或询盘截图（打码）作为社会证明
